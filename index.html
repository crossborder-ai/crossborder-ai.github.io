CrossPilot｜跨境运营 AI 助手

对着电脑说话，库存和补货建议就来了。

CrossPilot 是一个跑在你电脑上的跨境电商 AI 助手。 你可以直接问它库存、断货风险和补货建议；数据留在本机，不用把经营资料交给第三方服务器。

本地对话示例
你问 哪些 SKU 这周有断货风险？按最近销量给我补货建议。
CrossPilot 回答 我先查了库存和近 30 天销量。A12、B07、C19 风险最高， 建议优先补 A12 180 件、B07 120 件、C19 90 件。 需要的话，我可以继续按仓库和供应周期再拆一版。

它是什么

先回答三个问题：这是什么、给谁用、能解决什么问题。

给跨境卖家和运营用

适合每天要看库存、算补货、追进度的人，不用先学一堆菜单路径。

把重复查询变成一句话

你直接问问题，它替你查数据、整理结果、给出建议。

对决策负责，不只吐表格

不是单纯返回数字，而是给出“该补多少、先补谁、为什么”的建议。

它适合谁

把技术词放后面，先说清楚用户能不能直接用。

核心用户

亚马逊卖家、运营、库存管理人员。主要诉求是少翻表、少做手工判断。

进阶用户

懂技术的独立开发者或服务商，可以看领星接入、工作流和本地运行方式。

不适合的场景

如果你想要的是纯云端 SaaS、而且不接受本地安装，那这版不是最合适的入口。

它能做什么

每个功能都配一个问句示例，减少理解成本。

库存分析

查库存、看断货风险、看趋势变化。

例如：哪些 SKU 快断货了？

补货建议

基于库存和销量，给出补货数量建议。

例如：按最近 90 天销量，这三个产品建议补多少？

后续扩展

利润分析、广告、选品等能力会继续补，但页面会明确标注 Roadmap。

例如：这批产品的利润结构能不能一起看？

怎么用

把最关键的安装和启动放这里，首页不再像 README。

1

安装

先准备好 Node.js 22+ 和 bun，然后运行安装脚本。

curl -fsSL https://raw.githubusercontent.com/crossborder-ai/CrossPilot-releases/main/install.sh | bash

脚本会自动处理镜像、下载最新构建包并注册 `crosspilot` 命令。

2

启动

安装完成后，在任意终端输入 crosspilot 即可。

crosspilot

会自动拉起本地服务并打开浏览器，不需要切到安装目录。

3

关闭

关闭浏览器标签页后，服务会在约 30 秒内自动退出。

不需要长期挂着终端；需要重新使用时，再输入一次 crosspilot。

高级说明

如果你还没装好环境，可以先检查版本：

node -v bun -v

Homebrew 用户可用 brew install node@22 bun；没有 Homebrew 的，可以先装 fnm，再装 Node 22 和 bun。

详细的命令、领星配置和环境变量说明，以 CrossPilot-releases 仓库 README 为准。

数据与安全

把“本地运行”翻成用户能理解的话：数据不出本机。

本地保存

账号数据、配置和会话都保存在你自己的电脑上，不经过第三方服务器。

最小权限

只接入你显式配置的领星数据源，不预设多余权限或隐藏同步。

诚实边界

当前只支持领星接入，其他 ERP / 平台会明确标成 Roadmap，不会写成已支持。

更新与路线图

把“早期”说清楚：现在是内测和共创阶段，不是装成熟。

当前阶段

种子用户内测中。会持续补真实场景、真实截图和可验证结果。

短期计划

补充案例墙、FAQ、更多使用示例，以及更完整的反馈入口。

中期路线

逐步扩展到利润分析、广告和更多经营数据源，但会先按页面标注再上线。

常见问题

早期页面要把疑问提前说掉，减少访客跳出。

为什么首页不把安装命令放在最前面？

因为第一次来的访客先需要知道它是什么、给谁用、能解决什么问题。安装说明已经保留，但放在“怎么用”里更合理。

它和通用 AI 工具有什么区别？

CrossPilot 已经接好了领星数据，目标是直接处理跨境运营里的库存和补货问题，而不是给一段通用回答。

它会把数据上传到别的服务器吗？

不会。当前设计是本地运行，数据和密钥留在本机。
